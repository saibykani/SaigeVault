# ADR-0008: Native mobile clients (SwiftUI, Jetpack Compose) with no business logic

**Status:** Accepted · **Date:** 2026-10-01

## Context

The mobile apps need first-class camera and document scanning (VisionKit, CameraX/ML Kit), share-sheet extensions, biometric unlock, Keychain/Keystore and encrypted offline caches. These are platform APIs where cross-platform frameworks add friction.

## Decision

- **iOS: Swift 6 + SwiftUI**, iOS 17+, Observation framework, strict concurrency. The Xcode project is **generated by XcodeGen** from `apps/ios/project.yml`, so no `.pbxproj` merge conflicts. Personal signing values live in a git-ignored `Config/Local.xcconfig`.
- **Android: Kotlin + Jetpack Compose**, minSdk 28, Gradle version catalogs.
- **Neither client contains business logic.** Classification, extraction, search, RAG, agent and authorization all live in the backend. Clients render state and collect input.
- Mobile security baseline: App Lock (Face ID / Touch ID / passcode), app-switcher privacy shield, HTTPS-only in release builds, no backups of vault data, ephemeral URL caches.

## Consequences

- UI work is duplicated per platform. Shared copy and the feature registry are mirrored by hand for now, and tests assert phase numbers stay in range.
- iOS cannot be built on Windows/Linux. CI builds and tests it on a macOS runner, and installing on a device requires a Mac with Xcode.
